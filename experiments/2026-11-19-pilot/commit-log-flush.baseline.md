**로그 flush**는 메모리에 있는 로그를 **디스크에 실제로 써서 저장하는 것**을 말합니다.

### 왜 필요한가
DB는 성능 때문에 로그도 일단 **메모리(log buffer)** 에 먼저 적어둡니다. 그런데 메모리는 정전이나 서버 크래시가 나면 사라집니다. 그래서 커밋 시점에는 이 로그를 **디스크로 내려보내서** 안전하게 만들어야 합니다. 이 작업이 flush입니다.

### 흐름
1. 트랜잭션이 데이터를 변경함
2. 변경 내용이 **로그 버퍼(메모리)** 에 기록됨
3. `COMMIT` 요청이 들어옴
4. 로그 버퍼를 **디스크의 로그 파일에 기록하고 flush** (보통 `fsync` 호출로 OS 캐시까지 확실히 디스크에 내림)
5. flush가 끝나면 DB가 "커밋 성공"이라고 응답

### 비유
메모장에 적어둔 것(메모리)을 **저장 버튼을 눌러 파일로 저장**(디스크)하는 것과 비슷합니다. 저장 전에 컴퓨터가 꺼지면 날아가지만, 저장 후에는 남아 있습니다.

### 왜 로그만 flush하고 데이터 파일은 안 하나
- 로그는 **순차적으로 이어 쓰기**만 하면 되어서 빠름
- 데이터 파일은 여기저기 **흩어진 위치(랜덤 I/O)** 를 수정해야 해서 느림
- 로그만 디스크에 있으면, 장애 후 **로그를 다시 재생(redo)** 해서 데이터를 복구할 수 있음

그래서 `COMMIT` 때는 **로그만 확실히 디스크에 저장**하고, 데이터 페이지는 나중에 천천히 반영합니다.

### 참고
MySQL InnoDB에서는 `innodb_flush_log_at_trx_commit` 설정으로 이 동작을 조절합니다. 값이 `1`이면 커밋마다 flush해서 가장 안전하고, `0`이나 `2`면 더 빠르지만 장애 시 최근 트랜잭션이 유실될 수 있습니다.
